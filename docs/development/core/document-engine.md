# Document-engine migration

The document-engine work preserves each format's original source while replacing whole-document work in editing paths. Source editing, visual authoring, preview and final compiler layout are separate capabilities. A preview or a raw-source dialog does not establish visual editing support.

## Persistent source foundation

`src/shared/source-buffer.ts` implements an internal persistent piece B+ tree. Published snapshots own immutable nodes and chunk ranges. A local replacement copies affected paths and bounded descriptor arrays; untouched chunks and subtrees remain shared. Splits and joins restore node occupancy, including after bulk deletion. The initial experimental defaults are 32 children per branch, 64 pieces per leaf and 4,096 UTF-16 units per original chunk. These are candidates pending integrated editor measurements, not established optimal constants.

Each chunk has private sparse coordinate indexes. Subtree summaries combine raw UTF-16 length, normalized length, UTF-8 size and logical newline count, including CRLF and surrogate pairs crossing piece boundaries. Raw positions inside CRLF are not normalized editor positions. Exact edits also reject split surrogate pairs. Streaming encoding carries a pending high surrogate across chunks. This describes encoding of the source string; it does not introduce a new policy for decoding invalid file bytes.

`SourceOperation` contains one document identity, base/result versions, operation identity, origin, history group and sorted disjoint raw changes. The store validates all changes before publication. Preparation returns a private capability; forged, consumed, aborted or stale preparations cannot commit. Inverse edits use post-state coordinates and expand only where necessary to restore a newly formed CRLF or Unicode seam. Undo is a new operation with a higher content version.

Snapshots remain readable after edits and compaction. Compaction changes the storage epoch without changing the content version. JavaScript reachability currently retains chunks needed by snapshots; session-level history, job ownership, journal and save integration must provide the corresponding retention bounds. Mutable hot gaps and transferable shared backing buffers are not used.

Insertions share a private append-only arena. Each published piece freezes its readable range; later writes only extend the allocation beyond that range. Sparse prefix entries below an existing extent never change. Consecutive ranges in source order coalesce into one piece, while separate cursors may share storage without sharing an occurrence. Aborted preparations can leave unused slots. The writer retains at most one chunk; gaps in chunks still referenced by live pieces require compaction. Compaction seals the current writer. Arena typed arrays and writer handles never leave the kernel. Counters distinguish allocated and written arena units, and benchmarks include external/ArrayBuffer memory as well as JavaScript heap use.

`SourceMaintenance` schedules a storage audit after 500 ms of quiet, once 256 edits or 256 Ki UTF-16 units of editing have accumulated. The native replica also audits its first accepted edit. The audit yields per bounded tree node, counts each backing chunk once, includes the current writer, and does not scan source text. It compacts only when unused capacity is at least 256 Ki units and allocated capacity is at least twice the current source length. These initial conservative thresholds are measured with `scripts/benchmark-source-maintenance.mjs`; integrated workload tuning remains pending. Capacity is a UTF-16 upper bound, not a measurement of V8 string heap representation.

Rebuilding yields after a chunk or 64 input pieces and constructs bounded right-spine paths. Scheduled slices target one millisecond; an indivisible step or runtime pause can exceed that target. New input, reidentification and disposal cancel session work. Only a private prepared capability can publish the new root; text version and document identity stay unchanged. Sessions notify storage readers separately, so CodeMirror adopts the new source without a text/selection transaction, rich echoes can prove ownership across the swap, and native dirty/recovery checks accept only owned snapshots of the same text generation. Parser owners and completed trees remain valid; an unfinished parser may pin its previous equivalent input until completion or cancellation.

Maintenance retains one audit/build job per session or worker replica and its old/new overlap. It cannot reclaim chunks explicitly held by saved baselines, asynchronous saves, compatibility facades, parser input or callers. Global inactive-tab/job/cache budgets remain unfinished; this is not a process-wide memory plateau guarantee.

Native document replacement and tab activation release the previous maintenance owner. A save completing with an owned pre-compaction snapshot uses the current content identity, preventing an unchanged document from briefly becoming dirty after deferred equality reconciliation. `node --expose-gc scripts/check-source-compaction.mjs` checks repeated grow/fragment/compact cycles without external snapshot owners: its recorded 12 cycles retain one of 36 tracked roots and one of 972 tracked chunks. Saved/history/caller ownership remains outside that isolated check.

Original chunks own detached UTF-16 strings. A small substring must not retain its original full document through a JavaScript sliced-string parent. Chunks also share one store-owned metric callback; a callback created inside a build closure can otherwise keep the entire piece array alive. Atomic/legacy message parsers, inverse edits and composed history text detach retained strings too. Privately branded, deeply frozen messages can skip repeated copying within the same realm; caller-frozen objects and IPC copies still undergo validation.

Run `node --expose-gc scripts/check-source-storage.mjs --assert` and `node --expose-gc scripts/check-operation-storage.mjs --assert` for isolated retention checks. In the recorded Node probe, deleting an 8 MiB source down to 4 KiB initially retained 2,048 chunks, about 10.06 MiB of heap and 6.05 MiB of ArrayBuffers. The ownership fixes retain one chunk, about 0.28 MiB of heap and 0.003 MiB of ArrayBuffers. Two retained 4 KiB operation slices initially pinned about 16 MiB of parent strings; detached payloads use about 0.03 MiB in that probe. These are isolated measurements, not process-wide memory guarantees or integrated latency results. Copying original text has a cold-load cost that remains part of the performance evaluation.

`DocumentSession` adds grouped source/visual history and stable metadata subscriptions without a UI dependency. It composes exact edit batches without diffing the document. Source and metadata advance before recovery is synchronously enqueued, the active view reconciles, and observers are notified. Undo and redo produce new operations. Reentrant edits are rejected at that observation boundary; an observer failure cannot roll back accepted source.

History retains at most 128 groups and 8 MiB of estimated operation payload per session by default. The renderer runtime additionally caps the combined history at 512 groups and 32 MiB. It accounts for completed operations without walking all open tabs, and trims older history from less recently used sessions first. Activating a tab refreshes its priority. Closed or replaced sessions release their accounting and subscriptions. These limits cover retained undo/redo payloads, not current documents, saved baselines, accepted operations still reconciling, or snapshots explicitly held by callers.

Trimming history preserves current source, version, selection and saved identity. It drops the oldest undo groups or the far end of redo so the remaining chain stays executable. Accounting updates before history observers run; an accepted native edit defers its history notification until view reconciliation finishes. Grouped operations have separate count/size bounds. Saved snapshots refer to a specific version, so finishing an older save cannot clean newer changes. Undo uses known content identities; returning to saved text through another edit path runs a cancellable, chunked equality check after input. Dirty state stays conservative until that exact comparison finishes.

Run `node --expose-gc scripts/benchmark-runtime-history.mjs` to measure grouped and isolated source operations with eight inactive tab histories and 1k/10k/100k-line Unicode/CRLF documents. Each case warms up with 200 edits and measures 1,000 more, reporting percentiles, history payload estimates, source counters and memory after storage maintenance. An optional first argument selects another checkout's `src/renderer/src/document-runtime.ts` for a matched baseline. This Node probe excludes editor DOM, IPC, rendering and native saves; it cannot establish the complete input or visual performance gates.

History owns exact forward/inverse changes, the original source length, selections and content identities. It does not retain a full before/after source root for each group. Saved baselines and snapshots explicitly held by views or callers remain valid. `node --expose-gc scripts/check-source-retention.mjs` checks that only the current root remains reachable among 40 edited roots while all 40 undo/redo steps stay exact. This is an ownership check, not a complete arena-memory plateau benchmark.

Native recovery uses the buffer for both legacy replacements and atomic operations. The renderer retains a session per open tab. Ordinary CodeMirror input converts accepted changes directly into one atomic operation before view callbacks; external operations update changed normalized ranges. Raw selection anchors and shared history survive editor remounts and tab identity changes. The SDK's CodeMirror undo/redo commands and Vim route to host history; standalone addon-created editors retain native CodeMirror history behavior.

The native dirty indicator maintains dirty-tab membership instead of copying and scanning every tab for each incoming operation. Active edits update one entry; closing, resetting, saved-text verification and explicit tab snapshots keep membership consistent. Pending workspace files remain dirty even when empty. Reordering tabs preserves membership. A shared window guard writes the native flag only when its value changes.

A recreated source editor initializes its native selection from the session's raw bookmark instead of resetting to the start. Conversion uses the current snapshot's mixed-line-ending and UTF-16 mapping. Restoration itself does not create an edit/history entry or publish a source operation. Native tab tests cover a selected word after an emoji and CRLF, switching away/back, and exact unchanged source. Rich visual caret/bookmark parity remains separate migration work.

Rich editing now commits the actual accepted Tiptap candidate, including appended transactions, before its public `beforeTransaction` callbacks. The standard dispatcher still applies filters exactly once. An accepted-edit handle keeps the source reentrancy guard until the native view and its callbacks finish; document observers run afterward. A save requested inside a rich callback therefore sees the queued source operation. A rejected filter or oversized edit cannot partially change source/history/view. The current full rich serializer remains a compatibility path and is not a bounded visual inverse.

Only host-tagged source echoes bypass rich source production. `emitUpdate: false` controls Tiptap update events; it does not leave accepted editor text outside recovery. Echoes carry an immutable source snapshot and are checked against the active document. An addon that vetoes or changes an echo produces a visible synchronization error; subsequent stale-view edits are rejected, and **Retry** restores the canonical source after the addon is corrected. Small per-editor source stamps avoid retaining an initial full source root. Dispatch scopes keep nested undo synchronization from being mistaken for another user edit.

Legacy full-document reads are immutable snapshot facades with explicitly materialized string getters. Range-aware annotations avoid those getters. Whole-source compatibility transforms and current rich serialization still use a full-source boundary, and the current rich pane remains a complete model. Removing hidden rich work, bounding visual models and migrating default full-source consumers remain separate unfinished parts of this migration. Existing desktop size and execution guards remain in force. No large-file visual performance claim follows from the source bridge alone.

## Recovery admission and checkpoints

Source and rich edits use one preload journal. Before committing source, history or the editor view, the session checks journal capacity. Saturation rejects that attempted edit with a notice; previously accepted edits stay intact. Save retries recovery, and editing can resume when capacity is available. The normal admission budget is 8 MiB of estimated retained UTF-16 payload and range overhead, including outstanding transport calls. An empty journal allows one bulk message up to 40 MiB; its transport can retain a second copy. These are conservative accounting limits, not measurements of Electron wire traffic or total process memory. Native document-size validation still applies independently.

Delivery has a five-second deadline and three background retries, after 100 ms, 500 ms and two seconds. Manual save/close barriers can retry after that budget. A timeout cannot cancel Electron IPC: an outstanding transport is reused until it settles, and its bytes remain accounted even after a verified checkpoint retires the queue entry. Recovery controls likewise permit only one outstanding request. Thus repeated retries cannot accumulate abandoned full checkpoint or operation payloads.

Native duplicate receipts retain at most 128 operations and 8 MiB of estimated payload. A barrier that cannot recover through ordinary retries pauses new sends, captures the renderer's current checkpoint, reads the native head and replays the exact contiguous pending suffix. Native verification compares complete source, identity and version in bounded chunks, yielding between work slices and rejecting a changed text generation or foreign store. An owned storage-only replacement remains valid. Only a matching checkpoint retires older pending entries whose receipts expired. Edits accepted during verification wait in the same queue and are delivered afterward. The checkpoint is read-only: it cannot overwrite different native content or conceal a missing operation.

The internal recovery-state API distinguishes queued payloads, outstanding transport payloads, failed/retrying delivery and the latest memory acknowledgement. The session owns the local version; normal document state owns the file-saved baseline. A memory acknowledgement provides renderer-crash recovery, **not** a disk-durable acknowledgement. Loss of the replica's source beyond the available operation suffix remains a recoverable error; this protocol does not claim whole-app crash recovery or authorize an unverified bootstrap overwrite.

## Incremental parser input

`source-parser.ts` gives Lezer a normalized UTF-16 `Input` backed by an immutable source snapshot. Chunks start at the requested offset and have a bounded size. Complete range reads are counted separately. Source operations map Lezer fragments using normalized pre/post coordinates, including CRLF seams. Partial work is canceled on the next operation; retained fragments still receive every ordered change. Dialect/parser changes discard incompatible reuse.

Only complete, full-length trees are published as complete. `advance()` is an indivisible parser step whose duration is measured; scheduling it with a timer does not turn it into bounded or isolated work. Fragment retention has a fixed cap. Tests compare incremental CommonMark and GFM trees against full parsing. The document worker runs these sessions with coarse owner indexing; complete Hibi/addon dialect proofs and editor semantic consumers remain unfinished. This module does not claim resumable checkpoints for `marked`.

## Paged source-owner order

`source-owners.ts` provides an immutable order and position index for contiguous coarse owners. Leaves contain bounded record pages; directory nodes store owner counts and source lengths. A prefix insertion copies touched pages and directory paths, without changing later owner records or writing their absolute positions. Updating one owner preserves its slot and increments its record revision. Handles include a store epoch; slots are monotonic and never recycled in that epoch. Source offsets and slots retain safe-integer arithmetic across the 32-bit boundary.

The prototype supports configurable 128/512/4096-record pages for comparison, counts copied/queried slots and validates balanced occupancy. Tests cover 1,500 random splice sequences, retained snapshots, 100k-owner locality, numeric overflow and immutable records. Pages also summarize incomplete owners, so a pending-range query skips complete subtrees. Pending traversal and partial invalid-count queries include page and directory reads in those counters; closing a pending iterator stops further traversal.

`markdown-source-model.ts` connects accepted operations to this coarse index and the completed CommonMark/GFM CST. Input updates only touched owner spans; deleting a complete separator also invalidates its neighbors. Reconciliation expands those regions to complete old/new top-level Markdown boundaries and neighboring trivia. Unchanged owners retain their identities. This is coarse membership/coverage, not proof that inline references, style dependencies or render artifacts can be reused. Nested parent/child indexes, overlapping annotations and production view attachment remain unfinished.

The model avoids a full metadata walk through Lezer's rebuilt anonymous balancing nodes. A 100k-line prefix test checks bounded metadata visits and writes, but final parser assembly can still have a long indivisible step. Parser isolation and further partitioning remain required before making input-latency claims. Run `node --test tests/markdown-source-model.test.mjs` for randomized source/owner agreement, prefix locality, shared syntax payloads with distinct owners and dialect invalidation.

Dirty-region expansion resolves only its two boundary blocks. Re-enumerating the growing interior is quadratic when an inserted fence changes later fence pairings. `node scripts/benchmark-markdown-reconciliation.mjs` reproduces that case; the recorded 1,024-fence probe drops from 265,734 host-visited syntax nodes to 2,569. Boundary resolver calls are counted separately; internal Lezer resolver work is included in wall time, not falsely counted as instrumented host visits. Owner range iteration also counts bounded directory/page reads. Large syntax changes still require work proportional to affected owners; this does not establish constant-time parser convergence.

## Derived worker and source find

Source find lazily creates a trusted core worker. Bootstrap traverses one immutable source in bounded chunks, yielding while collecting them; `SourceStore` can consume an iterable without joining a complete string. Ordinary updates send ordered atomic operations. Replies name the worker epoch, source version and query request, and cannot apply to a newer document or selection request. The derived worker can be terminated and rebuilt when its operation queue exceeds 8 MiB; the canonical/native recovery journal is unaffected. The client retains one active bootstrap root, one outstanding query and its latest replacement. A canceled collector releases its previous root at the next yield, allowing brief old/new overlap. Cancellation acknowledgements bound query traffic, and only one automatic worker restart is allowed per document identity before reporting an error.

The worker applies the same quiet-time storage maintenance policy. Search indexes adopt only trusted storage swaps without discarding valid counts/checkpoints. An in-flight scan can finish on its immutable previous input; edits cancel that scan, and replica replacement, failure or disposal releases the maintenance owner. This bounds the number of retained jobs, while complete process memory still includes explicit caller/cache ownership.

`source-search.ts` runs a chunked linear literal matcher over normalized source, retaining query-length provenance and at most 128 matches per yielded batch. Case-insensitive NFKD normalization, expanded-character precision and non-overlap behavior are checked against CodeMirror's native cursor. Query input and normalized query length are limited to 65,536 UTF-16 units. A sparse index retains one rank/restart checkpoint per 1,024 matches, plus the first and last match; it does not retain all matches. Caret-relative navigation resumes from a predecessor checkpoint. Incomplete or canceled scans cannot publish complete coverage.

SourceEditor delegates complete match counting and next/previous lookup to that worker. It keeps CodeMirror's existing viewport highlighting, and rich-text find still uses its existing ProseMirror implementation. Regex isolation, exact replace-all, richer semantic search, parser/owner attachment, unified render scheduling and replacement of any expensive native highlighting paths remain unfinished. Bootstrap structured cloning and worker memory/latency still require integrated scale measurements; this stage does not establish the full large-file performance gate.

Run `node --test tests/source-search.test.mjs tests/source-search-index.test.mjs tests/document-worker-service.test.mjs tests/document-worker-client.test.mjs` for Unicode/oracle equivalence, bounded match retention, near-caret lookup, source replication, cancellation, stale generations, backpressure and finite restarts. `tests/find.test.mjs` checks real worker loading, source/rich switching, Unicode matching, offscreen and dense navigation, focus and source preservation in Electron.

## Standalone source views

Standalone formats use a source/preview shell without creating a hidden Tiptap editor or attaching rich extensions. Source view does not mount the format preview or read the full document merely to pass preview/Markdown-flavor props. Switching to split view mounts the preview on demand; returning to source view releases it while keeping the CodeMirror view, selection and host history. Pane focus and transition behavior share the same lifecycle as Markdown. The welcome check uses canonical source length, and projection-only imports no longer pull in the rich editor constructor.

Rich view effects must tolerate an editor instance whose view has not mounted yet. Spellcheck applies on mount and after preference changes; deferred mirror-cursor measurement skips absent views. Lazy preview loading stays inside its own Suspense boundary so it cannot remove the active source surface.

This is a standalone-format boundary. Markdown source view still owns the existing rich controller for semantic consumers, and enabled addons may explicitly request whole-source compatibility reads. Full source-only Markdown loading, semantic consumers and bounded preview publication remain separate gates. `tests/source-format-lifecycle.test.mjs` checks rich attachment, preview lifetime, source view identity, exact CRLF edits, undo/redo, find and saving across pane changes.

Shared format addons register source-language loaders without constructing parsers. HTML, Markdown, LaTeX, Textile and R implementations load only when their registered language is requested by an editor or highlighter. Aliases share an in-flight load; a revoked registration cannot replace its successor when it finishes. Failed loads remain stopped until an explicit **Retry language** action, which keeps the existing source view and canonical history. This uses the existing `CodeLanguage.load` API; it does not make rich schema, preview or compiler activation fully lazy.

The generic source surface also leaves Markdown-specific source support unloaded. A separate Markdown source entry supplies the complete CodeMirror language support, including list keymaps and HTML completion, only when that source surface opens. An HTML or plain-text source view does not load it as a side effect.

## Bounded metadata service

The same derived replica supports a separately requested CommonMark/GFM metadata lane. Its parser module loads only on metadata demand. Renderer workers use ES-module output so this module remains a separate production chunk. An operation updates the existing parser/owner model; a storage-only swap preserves its owner identities. The service publishes only completed parse results. It rejects unknown dialects, stale versions and invalid raw ranges before starting work. This parser scope is not a claim of complete Hibi flavor, syntax-preference or third-party addon parity.

Metadata requests can opt into frontmatter ownership. This separately loads YAML recognition and a projected parser. The source-backed reader matches the existing closed-mapping behavior, including malformed mappings, BOM, mixed line endings, Unicode separator closures and trailing blank lines. It reads chunks cooperatively and materializes only the closed YAML candidate. YAML parsing itself remains indivisible inside the worker. Completed recognition retains only scalar bounds and the inspected prefix extent; body-only edits beyond that extent reuse it, while an append invalidates an EOF-sensitive result.

The projected parser gives the exact body range to Lezer and restores full-document coordinates around an opaque `Frontmatter` owner. It shares balanced body trees rather than flattening their children. This also handles a Unicode separator that the frontmatter regex accepts but Lezer does not consider a new line. Body edits retain parser fragments and owner identity; changed prefix recognition or normalized length discards incompatible parser state. Replies identify this configuration as `commonmark+frontmatter` or `gfm+frontmatter`. Run `tests/source-frontmatter.test.mjs` and `tests/frontmatter-source-model.test.mjs` for differential recognition, projected-body parsing, randomized edits, read-set invalidation, cancellation, compaction and local owner-update checks.

`MarkdownSourceModel.page(from, to, limit)` returns at most 256 coarse owner records with raw source ranges, source version, dialect, owner namespace, completeness and a continuation offset. A caret query includes its containing owner, including the final owner at EOF. Rows do not contain the complete source or CST. Local callers may inspect mapped, incomplete coverage, but it cannot authorize a visual inverse. The worker waits for complete coverage before publishing a page.

`SourceOwners.bySlot(slot)` resolves an arena-local owner handle in that exact immutable snapshot. A lazy reverse cache stores page membership and parent links rather than absolute positions. Once requested, edits update changed pages and retire removed handles; prefix insertion does not rewrite later offsets. Historical snapshots remain readable and can reselect the cache's indexed root. The cache retains one root's rows per arena, reported by `counters().locator`, and is released with the arena. The first lookup still indexes all owners, so cold construction belongs off the input path; this does not establish bounded cold initialization or complete semantic dependency tracking. `tests/source-owner-locator.test.mjs` covers retained roots, random edits/removals, 100k-owner prefix locality and wide numeric coordinates.

`changesSince(previous)` reports changed and removed record identities within the same arena. Merely shifting an unchanged record does not invalidate its payload. Reference metadata uses this distinction: `SourceReferences` keeps the first definition in document order, with indexed candidate heaps for duplicate normalized names. It reparses changed owners and affected trivia/EOF context through a supplied reader. That reader must use the same immutable source snapshot and grammar; the index does not invent label normalization. Prepared reader results are validated and copied before existing definitions change.

Reference read scopes provide a lookup view for a semantic lexer, recording both resolved names and misses without copying the entire dictionary. A changed winning candidate invalidates readers of that name; editing an unrelated or non-winning definition preserves their scopes. Mixed reads cannot later become valid again, and disposal invalidates every scope. Stored strings own their backing data, and scopes retain only the candidates they read. These are semantic dependency proofs, not permission to edit a definition or guess its literal source range.

The reference index is currently a core prerequisite, not an attached worker or renderer consumer. Its initial owner walk is linear; large-container parsing, cooperative startup, cache budgets, nested metadata and complete Hibi syntax parity remain separate gates. `tests/source-references.test.mjs` checks failure atomicity, lifecycle, duplicate/missing definitions, randomized updates, 100k-owner locality and regional Marked equivalence with CRLF and randomized block edits.

Find and metadata share bootstrap and ordered operations while keeping independent active/latest requests, cancellation acknowledgements and deadlines. Replica acknowledgements have their own deadline too; traffic in one lane cannot keep a stalled other lane alive indefinitely. Closing metadata requests owner release, with an acknowledgement distinct from ordinary query supersession. Bounded automatic restart reconstructs the derived replica while leaving canonical recovery intact. Find receives priority between metadata slices, with metadata aging. Metadata batches cheap parser advances within a two-millisecond slice instead of paying one timer turn per block. An individual Lezer advance remains indivisible and can exceed that target; its real duration must still be measured.

The lane is an internal service prerequisite. Editor outline, statistics and bounded visual consumers still require format-specific semantic integration; the existing full rich model has not been removed. Run the worker/client/model tests serially for this integration. After building, `tests/document-metadata-worker.test.mjs` verifies the emitted lazy module in Electron, shared find, exact source updates, parser-owner release/reacquisition and the separately enabled word-count worker.
